# CLAUDE.md — bww-abc

Context for AI assistants working in this repository.

## Purpose

Two-way conversion between Bagpipe Music Writer (`.bww`) and ABC notation, shared
publicly for other pipers:

- `bww2abc`: BWW → ABC. A port of `bww2abc.js` by Jean-Francois Moine (GPL3+). It
  also reads legacy pre-Gold `.bmw` files.
- `abc2bww`: ABC → BWW Gold, for pipe-tune ABC as written for abcm2ps.

Say "BWW" everywhere. Use "BMW" only for the legacy pre-Gold format, or for the
Bagpipe Music Writer program itself. A Rust port (CLI binaries plus WASM for a web
page) is a possible future step; the Python stays the reference implementation.

## Layout

```
bww_abc/
  __init__.py       bww2abc CLI; exposes convert()
  converter.py      BWW (Gold + legacy) → ABC, single-pass token scanner
  grace_notes.py    GRACE and DECO tables (~200 embellishments) — shared by both directions
  abc_parse.py      pipe-tune ABC subset → abc_model.Tune
  abc_model.py      Tune, Line, Note, Bar, Ending…
  rhythm.py         note length ↔ BWW denominator + dots
  grace_reverse.py  (grace group, next note) → BWW embellishment token
  grace_prefs.py    GENERATED by scripts/build_grace_prefs.py (token counts only)
  bww_writer.py     Tune → BWW Gold text
  abc2bww.py        abc2bww CLI
docs/               format references and design notes (start with conversion_notes.md)
docs/reference/     Moine's bww2abc.js and MuseScore's BWW lexer
tests/              pytest; fixtures/abc/ holds tunes from Ed's own collection
```

## Where things are documented

- `docs/conversion_notes.md`: design decisions for both directions, the
  embellishment lookup order, structure mapping, testing approach, known
  limitations. Update it when behaviour changes.
- `docs/bww_format.md`: BWW Gold tokens.
- `docs/bmw_legacy_format.md`: the pre-Gold format.
- `docs/abc_bagpipe.md`: ABC for pipes.

## Traps (each has bitten before)

1. `space` tokens are visual spacers; ignore them.
2. Two-letter dot suffixes (`'la`, `'ha`): match dots with `re.match`, not
   `re.fullmatch`.
3. `"2nd Part"` labels are standalone quoted lines; detect them at line level.
4. Ties: Gold `^ts` writes `-` after the next note, so its gracenotes stay in
   front.
5. The time signature isn't always last on an `&` line; trailing tokens can be
   music (`I!''`).
6. Legacy files have no `Bagpipe…` first line and a positional header.
   `^t<pitch>` and `^3<pitch>` follow the note(s), so `^te`/`^3e` are old
   ties/triplets on E unless a Gold `^ts`/`^3s` is open.
7. A gracenote group can't end on its melody note's pitch (`{ed}d`); abc2bww
   warns.
8. Read files as UTF-8, falling back to Windows-1252. Gaelic accents matter.

## Adding an embellishment

When a token is reported as `*** 'xyz' not recognised ***`:

1. Decide whether it belongs in `GRACE` (a gracenote sequence) or `DECO` (an
   ABC decoration).
2. Check the name in `docs/bww_format.md` or the BMW manual.
3. Add it to `bww_abc/grace_notes.py`, using the pitch letters from the table in
   `conversion_notes.md`.

If the new token shares a grace string with an existing one, check
`_OVERRIDES` in `grace_reverse.py`.

## Purchased files: never commit

This repo is public. `private/` (git-ignored) and the Lee & Sons NAS folder hold
purchased BWW files. Never copy them, or ABC made from them, into the repo.
Test fixtures come only from Ed's na_maragan_collection (a private repo), and
never from tunes marked `B:Lee & Sons` or from purchased books. Never
`git push --mirror`: the local `refs/agents/…` checkpoint refs contain
purchased files.
