# ABC → BWW Converter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An `abc2bww` command that converts one or more of Ed's pipe-tune ABC files into Bagpipe Music Writer Gold `.bww` files that open in BMW Gold and import into Braw Tunes.

**Architecture:** Three stages in the existing `bmw2abc_converter` package: a parser for Ed's ABC subset → a small data model (`Tune` / `Line` / `Note` …) → a BWW writer that mimics Lee & Sons / BMW Gold output. Embellishments are resolved by reverse lookup of the existing `GRACE` table, disambiguated by the following note using a preference table generated from the Lee & Sons corpus.

**Tech Stack:** Python ≥3.12, stdlib only (`fractions`, `dataclasses`, `argparse`, `re`), uv, hatchling, pytest.

**Spec:** `docs/superpowers/specs/2026-11-26-abc2bww-design.md`

## Global Constraints

- Stdlib only; no new runtime dependencies.
- BWW header codes: `T` = title, `Y` = tune type, `M` = composer. Never write Lee's swapped form.
- Header tuples exactly: title `(T,C,0,0,Times New Roman,24,700,0,0,18,0,0,0)`, type `(Y,L,0,0,Times New Roman,14,700,0,0,18,0,0,0)`, composer `(M,R,0,0,Times New Roman,14,700,0,0,18,0,0,0)`.
- Boilerplate block (first line `Bagpipe Music Writer Gold:1.0` through `TuneFormat,(1,1,F,L,400,400,400,400,L,0,0)`) copied verbatim from `bmw-to-convert/Barren Rocks of Aden.bww` lines 1–13.
- Every lossy step appends a human-readable string to `Tune.warnings`; nothing is silently dropped except `%%` directives, `%` comments that aren't part labels, and header fields other than X T R C Q M L K V.
- **Never commit Lee & Sons files** or anything copied from `bmw-to-convert/`, `convert/`, or the NAS. The repo is public. Fixtures come only from `~/projects/eeferg/na_maragan_collection/tunes/pipe_*`.
- Corpus paths come from env vars and tests skip when unset/missing: `LEE_BWW_DIR` (Ed's value: `/run/user/1000/gvfs/smb-share:server=nas.local,share=share/Dropbox/_.piping/00.lee_and_sons/Light Music`), `NA_MARAGAN_DIR` (Ed's value: `~/projects/eeferg/na_maragan_collection`).
- Priority: marches, strathspeys, reels.

## BWW conventions (verified from the 97 Lee files)

The writer must reproduce these; they are facts, not choices.

```
& sharpf sharpc 2_4 I!'' E_8                       ← first staff: clef, key, time sig, repeat start, pickup
!	gg Fr_8 'f HGl_16		space		hdbf Fr_8 'f El_16
!	thrd D_4		space		lgstd D_8			''!I   ← staff ends with !t / !I / ''!I / !!t

"2nd Part"                                          ← part label: own line, blank line before
& sharpf sharpc  I!''  gg Fr_16 'f HGl_32          ← later staves: no time sig
```

- Each bar after the first in a staff is introduced by `!` (plain barline token at the start of the bar).
- Pitch → BWW: `G→LG A→LA B→B c→C d→D e→E f→F g→HG a→HA`. Dot letter: `lg la b c d e f hg ha`; single dot `'x`, double dot `''x`, placed right after the note token.
- Beaming suffix: notes of length ≤ 1/8 in a beam group of ≥ 2: first gets `r`, all others `l` (`Er_16 Fl_16 HGl_16`). A lone beamable note or any note ≥ 1/4 has no suffix (`E_8`, `D_4`).
- Tie: `^ts` immediately before the first note token (after its embellishment), `^te` immediately after the second note token (after its dot): `strlg ^ts LA_4 space LAr_8 ^te`.
- Triplet: `^3s` before the first note (before its embellishment), `^3e` after the third. Notes keep their **written** length (`^3s Er_16 Fl_16 HGl_16 ^3e`).
- Endings: `'1` / `'2` at the start of the bar; `_'` just before the barline that closes the ending. A `:|` directly followed by ending 2 is written as `_'` then plain `!` (repeat implied by endings): `!	'1 gg E_4 … !	D_4 ^te … lgstd D_2	_'` / `!	'2 E_4 …`.
- Rest: `REST_<denom>`.

## Review Focus

1. **ABC line ending mid-bar** (no barline at end of a source line) — expect the bar to continue on the next staff, a warning, and still-valid BWW. Test in Task 5.
2. **Grace groups with no named BWW token** (`{fege}`, `{eAfA}`, `{gBeBG}`) and groups containing low G — expect single-grace tokens plus a warning; a low-G grace (no single token exists) gets a warning, not a crash. Test in Task 3.
3. **Durations that don't map** (`c5` at L:1/8 = 5/8) — expect a warning naming the note and bar, and the nearest shorter mapped value used. Test in Task 2.
4. **Broken rhythm across a grace or bar**: `a>{g}b`, `a2>{GdG}B2` — broken rhythm still applies across the grace group. Test in Task 4.
5. **Windows line endings and odd headers** (CRLF files, two `T:` lines, `W:` lyrics after the music, `L:1/8 8 40`) — parse cleanly; first `T:` only; `L:` trailing junk warns. Test in Task 4.

### Task 1: Data model and rhythm mapping

- Test: `tests/test_rhythm.py`

**Interfaces:**
- Produces (`abc_model.py`), all `@dataclass`:
  - `Note(pitch: str, length: Fraction, grace: str = "", tie: bool = False, beam_start: bool = True)` — `pitch` is an ABC letter from `GABcdefga`; `length` is a fraction of a whole note **after** broken rhythm; `beam_start` is True when whitespace, a barline, or line start precedes the note (or its grace group).

  - `Bar(kind: str)` — one of `"|" "||" "|]" "[|" "|:" ":|" "::"`

  - `Tune(title: str, tune_type: str | None, composer: str | None, tempo: int | None, meter: str, lines: list[Line], warnings: list[str])`

  - `bww_duration(length: Fraction) -> tuple[int, int] | None` — `(denom, dots)`; `None` if unmappable.
  - `nearest_duration(length: Fraction) -> tuple[int, int]` — largest mapped value ≤ length (fallback for warnings).
  - `PITCH_TO_BWW: dict[str, str]`, `PITCH_TO_DOT: dict[str, str]` (values per "BWW conventions").

Lookup order in `embellishment_tokens`:
1. `GRACE_PREFS[(grace, pitch)]`.
2. Tokens `t` with `GRACE[t] == grace`: exactly one → it. More than one → first in `_OVERRIDES` (a small dict in `grace_reverse.py`, one comment per entry) else alphabetically first, with warning `"ambiguous grace {grace} before {pitch}: chose X from [..]"`.
3. Otherwise split into single-grace tokens (`A→ag B→bg c→cg d→dg e→eg f→fg g→gg a→tg`) with warning `"no named embellishment for {grace} before {pitch}; written as single graces"`. A `G` in the group has no single-grace token: omit it and add `"low-G grace in {grace} cannot be written"` to the warning.

### Task 3: ABC parser

**Files:**
- Create: `bmw2abc_converter/abc_parse.py`
- Test: `tests/test_abc_parse.py`

**Interfaces:**
- Consumes: model from Task 1.
- Produces: `parse_abc(text: str) -> list[Tune]` — one `Tune` per `X:` in file order.

Rules (from the spec's ABC subset survey):
- Normalise `\r\n`. Ignore lines before the first `X:`, `%%` lines, and header fields other than X T R C Q M L K V. First `T:` wins. `W:` lines are ignored anywhere.
- `L:` trailing junk (`L:1/8 8 40`) → use `1/8`, warn. Missing `L:` → 1/8. `Q:1/4=N` → `tempo=N`.
- `K:HP`/`K:Hp` both accepted; anything else → warn.
- `V:`: keep only items of the first voice seen; warn once per dropped voice `"harmony voice V:<id> dropped"`.
- `% <ordinal> Part` (regex `^%\s*(\d+(?:st|nd|rd|th)\s+Part)\s*$`, case-insensitive) → `part_label` on the next `Line`. Other `%` lines dropped.
- Each non-empty music line → one `Line`. Tokens: `{…}` grace (attached to the next note), notes `[A-Ga-g]` + length (`2`, `/`, `3/`, `//`, `3/2`…) × `L`, `z` rests, `-` tie, `(3` tuplet, `>`/`<`/`>>`/`<<` broken rhythm, barlines (longest match first: `:|`, `|:`, `::`, `|]`, `[|`, `||`, `|`), `[1`/`[2`/`|1`/`:|2` endings (`|1` → `Bar("|"), Ending(1)`), inline `[M:…]` → `Meter`, `"…"` chord/annotation dropped (one warning per tune with count), `!…!` decorations dropped (`!head-slashr!` warning text: "slash beat marks written as plain rests"), stray `.` dropped.
- Broken rhythm: `>` multiplies the previous note ×3/2 and the next ×1/2; `<` the reverse; `>>` ×7/4 and ×1/4. Applies across an intervening grace group.
- `beam_start` False only when the note (or its grace) directly follows the previous note/broken-rhythm marker/tie with no whitespace.
- Any other character → warning `"*** '<chars>' not recognised ***"` with line number.

### Task 4: BWW writer

**Files:**
- Create: `bmw2abc_converter/bww_writer.py`
- Test: `tests/test_bww_writer.py`

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces: `write_bww(tune: Tune) -> str` — complete file text; appends any new warnings to `tune.warnings`.
- `BWW_BOILERPLATE: str` (module constant; see Global Constraints).

Header: boilerplate, blank line, `TuneTempo,<tempo or 90>`, blank, then title/type/composer lines (omit type/composer when `None`), blank. Meter token: `C`→`C`, `C|`→`C_`, `n/d`→`n_d`.

Staves: one per `Line`. If `part_label`: blank line + `"<label>"` line before the staff. Staff text: `& sharpf sharpc` (+ ` <meter>` on the first staff only), then items in order:
- Bar at start of line: `|:`→`I!''`, `[|`→`I!`, `|`/`||` → nothing.
- Bar mid-line: `|`→`!` (as the opening of the next bar, on a new tab-indented physical line like Lee), `:|`→`''!I`, `|:`→`I!''`, `::`→`''!I I!''`, `||`→`!` + warning, `|]`→`!I`.
- Bar at end of line: `|`→`!t`, `||`→`!!t`, `|]`→`!I`, `:|`→`''!I`.
- Line with no final bar → no terminator, warning `"line N ends mid-bar"`.
- Ending handling, ties, triplets, beaming, dots exactly as in "BWW conventions". An open ending closes (`_'` before the barline) at the next `:|`, `||`, `|]`, `|:`, the next `Ending`, or end of tune; `:|` followed by `Ending(2)` writes `_'` + `!` instead of `''!I`.
- Note: `embellishment_tokens(...)` tokens, then `PITCH_TO_BWW[pitch]` + beam suffix + `_<denom>`, then dot token. Unmappable length → `nearest_duration` + warning `"line N: <pitch> length <len> has no BWW duration; wrote 1/<denom>"`.
- Rest: `REST_<denom>`.
- `Meter` mid-tune → its meter token.
